# Git Command Deep-Dive & Real-World Scenarios

### 1. `git squash`

- **السيناريو:** وأنا شغال على Feature جديدة، عملت كذا Commit صغيرة ورا بعض بأسماء زي (`wip`, `fix typo`, `test`). قبل ما أعمل Merge للـ Pull Request مع الـ `main` branch، بستخدم `squash` عشان أدمج كل الـ Commits دي في Commit واحدة نضيفة وبـ Message واضحة.
- **ليه بنستخدمه؟** عشان نحافظ على Git History نضيف ومنظم للـ Project من غير ما نصدر Commits مالهاش لازمة للتيم.

---

### 2. `git merge` vs `git rebase`

- **السيناريو:**
  - **`git merge`:** لو شغال مع التيم على ميزة وخلصتها وعايز أدمجها مع الـ `main`. الـ Merge بيعمل "Merge Commit" جديد يربط الـ Branches ببعض وبيحتفظ بتاريخ الـ Commits الحقيقي زي ما حصل.
  - **`git rebase`:** لو أنا شغال على الـ Branch بتاعي وزميلي نزل شُغل جديد على الـ `main` وعايز أخد التحديثات دي عندي. الـ Rebase بياخد الـ Commits بتاعتي ويحطها بعد آخر Commit نزل على الـ `main`.
- **ليه بنستخدمهم؟** الـ `merge` آمن وممتاز للتوثيق والـ Teamwork، أما الـ `rebase` بيخلي الـ History خطي ونضيف جداً من غير Merge Commits زيادات.

---

### 3. `git help`

- **السيناريو:** لو شغال من الـ Terminal ونسيت الـ Flags أو الأوبشنز الخاصة بأمر معين زي `git log` ومش فاكر بيتكتب إزاي بالظبط ومافيش إنترنت. بكتب `git help log` يفتحلي الـ Manual الكامل للأمر على الجهاز.
- **ليه بنستخدمه؟** للوصول السريع للـ Documentation المدمجة جوه Git من غير ما نخرج برة الـ Terminal.

---

### 4. `git cherry-pick`

- **السيناريو:** زميلي عمل Bug Fix ممتاز في Commit معينة على Branch تاني شغال عليه، وأنا محتاج الـ Fix ده عندي فوراً على الـ Branch بتاعي من غير ما أدمج الـ Branch بتاعه كله.
- **ليه بنستخدمه؟** عشان نختار Commit معينة وننقلها لـ Branch تاني بشكل منفصل.

---

### 5. `git clean`

- **السيناريو:** بعد ما عملت Build أو جربت كود، اتكريت ملفات كاش وTemporary Files كتير غير متتبعة (Untracked Files) وعايز أنظف الـ Working Directory وأرجعه نضيف زي ما كان بنقرة واحدة. بنفذ `git clean -fd`.
- **ليه بنستخدمه؟** مسح كل الملفات والـ Folders غير المتتبعة (Untracked) دفعة واحدة.

---

### 6. `git grep`

- **السيناريو:** شغال على Project كبير ومحتاج أدور على اسم Function معينة أو Variable متكرر فين في الكود المسجل في الـ Repository بسرعة من غير ما أفتح الـ Editor وأستنى السيرش بتاعه.
- **ليه بنستخدمه؟** للبحث السريع جداً جوه ملفات الـ Project المتتبعة من الـ Terminal.

---

### 7. `git blame`

- **السيناريو:** لقيت سطر كود فيه Bug ومش فاهم السطر ده اتكتب ليه بالشكل ده. بكتب `git blame filename` بيطلعلي مين اللي كتب السطر ده بالظبط، وفي أنهي Commit، وبتاريخ كام عشان أقدر أرجع أتناقش معاه.
- **ليه بنستخدمه؟** لمعرفة كاتب كل سطر كود والـ Commit والتاريخ بتوعها.

---

### 8. `git bisect`

- **السيناريو:** الكود كان شغال تمام، والنهاردة اكتشفت Bug، بس فيه أكتير من 100 Commit اتعملوا خلال الأسبوع. بدل ما أجربهم واحدة واحدة، بستخدم `git bisect` بيعمل Binary Search بين آخر Commit شغال وأول Commit فيه المشكلة لحد ما يحدد الـ Commit المسبب للمشكلة بالظبط خلال ثواني.
- **ليه بنستخدمه؟** لتحديد الـ Commit اللي تسببت في ظهور Bug بأسلوب البحث الثنائي.

---

### 9. `git shortlog`

- **السيناريو:** قبل ما نعمل Release جديدة، الـ Team Lead محتاج يعرف مين شارك بأد إيه في المشروع أو يعمل ملخص بالـ Commits المنجزة.
- **ليه بنستخدمه؟** لتلخيص وتجميع الـ `git log` بناءً على اسم كل Author وعدد الـ Commits اللي عملها.

---

### 10. `git prune`

- **السيناريو:** بعد فترة شغل طويلة واستخدام أوبشنز زي الـ Rebase والتنقل بين Branches كتير، بيبقى فيه Commits وأجسام غير متصلة بأي Branch (Unreachable Objects) مأثرة على مساحة الـ Repo.
- **ليه بنستخدمه؟** لتنظيف داتابيز الـ Git وحذف الأجسام الميتة/المهجورة لتوفير المساحة.

---

### 11. `git worktree`

- **السيناريو:** شغال على Feature جمدة وفجأة جالي Bug مستعجل على الـ `main`. بدل ما أعمل `git stash` أو أعمل Clone جديد للمشروع في مكان تاني، بعمل `worktree` جديد يخليني أفتح الـ two branches في فولدرين مختلفين وأشتغل عليهم في نفس الوقت.
- **ليه بنستخدمه؟** للعمل على أكثر من Branch في نفس الوقت في مجلدات منفصلة من غير تبديل بين الـ Branches.

---

### 12. `git verify-commit`

- **السيناريو:** لو شغال في مشروع Open-Source أو بشركة مشددة على الأمان، ولازم نضمن إن الـ Commit دي جاية فعلاً من صاحبها ومش حد منتحل شخصيته عبر مفاتيح التشفير (GPG Signatures).
- **ليه بنستخدمه؟** للتحقق من التوقيع الرقمي (GPG Signature) للـ Commit لضمان هوية الكاتب.

---

### 13. `git filter-repo`

- **السيناريو:** بالخطأ اترفع ملف فيه Passwords أو API Keys أو ملف مساحته كبيرة جداً في الـ History بتاع المشروع زمان، ومحتاجين نمسحه تماماً من كل الـ Commits القديمة كأنه ما اتكتبش قبل كده.
- **ليه بنستخدمه؟** للتعديل على تاريخ الـ Repository بالكامل لحذف ملفات حساسة أو بيانات قديمة.
